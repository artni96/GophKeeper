# Сервер

## Стек:
- Протокол взаимодействия клиента с сервером - `gRPC`;
- Формат взаимодействия клиента с сервером - `protobuf`;
- Метод аутентификации - `JWT`;
- СУБД: `postgres`;
- ORM: `GORM`.

## Документация
Документацией проекта являются `proto`-файлы, расположенные в директории `./api/proto`. 

## Описание стуктуры хранимых данных
На серверной стороне реализована бизнес-логика для пользователей (таблица `users`):
- Создание нового пользователя;
- Аутентификация полольвателя;

Также на серверной стороне имеется четёре вида сущностей:
- Пары логин/пароль (таблица `cards`);
- Произвольные текстовые данные (таблица `texts`);
- Произвольные бинарные данные (в процессе разработки);
- Данные банковских карт (таблица `logins`).

Каждая таблица имеет поля:
- `id` - уникальный идентификатор объекта (`uuid`);
- `user_id` - уникальный идентификатор автора (таблица `users`);
- `number` - уникальная последовательность для каждого пользователя;
- `title` - краткое наименование объекта;
- `description` - краткое описание объета;
- `created_at` - время создание объекта;
- `updated_at` - время последнего обновления объекта.

Общая бизнес-логика:
- Создание объета;
- Получение данных объекта по `number`;
- Обновление данных объекта по `number`;
- Удаление объекта по `number`;
- Получение массива объетов пользователя;


## Описание структуры хранимых данных
Каждое приватное поле имеет собственные `nonce` и `key_id`.
1. Таблица `cards` - данные банковский карт пользователя:
- `pan` - 16-ти значный номер (приватное);
- `holder` - имя владельца (приватное);
- `expiry_date` - срок действия (приватное);
- `cvv` - код CVV (приватное);
- `pin` - пин-код (приватное);
- `bank` - наименование банка;
- `brand` - наименование платёжной системы.

2. Таблица `logins` - данные логинов и паролей пользователя:
- `login` - логин (приватное);
- `password` - пароль (приватное);
- `url` - ссылка на ресурс.

3. Таблица `texts` - произвольные текстовые данные пользователя:
- `text` - текстовые данные (приватное).
