# GophKeeper

Приложения представляет собой клиент-серверную систему, позволяющую пользователю надёжно и безопасно хранить логины,
пароли, бинарные данные и прочую приватную информацию.

## Бизнес-логика сервера:
- регистрация, аутентификация и авторизация пользователей;
- хранение приватных данных;
- синхронизация данных между несколькими авторизованными клиентами одного владельца;
- передача приватных данных владельцу по запросу.

## Бизнес-логика клиента:
- аутентификация и авторизация пользователей на удалённом сервере;
- доступ к приватным данным по запросу.

## Схема взаимодетйсвия клиента с сервром.
### Сценарий подключения клиента к серверу.
1. Клиент подключается к серверу;
2. Регистрируется пользователь;
3. Пользователь аутентифицируется по логину и паролю;
4. Клиент инициализирует `gRPC streaming` для мониторинга изменений данных автозированного пользователя на сервере;
5. Клиент получает все необходимые ключи шифрования;
6. Клиент получает все зашифрованные данные пользователя;
7. Клиент расшифровывает данные при помощи ключей и сохраняет их в кэш.

### Сценарий обновления данных пользователя через клиента.
1. Клиент отправляет зашифрованные данные на сервер;
2. Сервер обновляется данные в СУБД;
3. После успешного обновления данных сервер отправляет всем активным клиентам данного пользователя соответствующее 
уведомление;
4. Клиент получает уведомление и информацию об обновленных данных;
5. Клиент запрошивает обновленные данные пользователя на сервере;
6. Клиент расшифровывает их при помощи ключей;
7. Пользователь имеет полный доступ ко всем своим данным на стороне клиента.


## Схема шифрования приватных данных

### Процесс создания ключей шифрования
В процессе регистрации пользователя для него создатся ключи шифрования:
1. Генерируется `salt` размером 16 байт;
2. Создается производный ключ `derived key` из соли `salt` и сырого пароля (в виде байтов) пользователя при помощи `pbkdf2`;
3. Генерируется ключ шифрования `aeskey` размеров 32 байта;
4. Создаётся cipher.Block `aesblock` посредством `aes.NewCipher` при помощи `derived key`;
5. Инициализируется блочный шифр `aesgcm` при помощи `cipher.NewGCM`, используя `aesblock`;
6. Генерируется вектор инициализации `nonce` размером 12 байт;
7. Создаётся `chiphertext` при помощи `aesgcm.Seal` из `nonce` и `aeskey`;
8. Шифруем `aeskey` ключ и получаем его зашифрованый вариент `encrypted_key` посредством создания слайса байтов из 
`nonce` и `chiphertext`;
9. В БД в таблице `user_keys` для пользователя создается запись с данными `salt`, `encrypted_key` и номером ключа `key_id`.

### Процесс получения ключей шифрования на стороне клиента
1. Пользователь аутентифицируется по логину и паролю;
2. Клиент запрошивает с сервера все ключи пользователя;
3. Клиент итерируется по всем ключам и для каждого:
- 3.1. создается производный ключ `derived key` из соли `salt` и сырого пароля (в виде байтов) 
пользователя при помощи `pbkdf2`;
- 3.2. Создаётся cipher.Block `aesblock` посредством `aes.NewCipher` при помощи `derived key`; 
- 3.3. Из зашифрованного ключа шифрования клиент получает исходные вектор инициализации `nonce` и `ciphertext`;
- 3.4. Клиент получает расшифрованный ключ шифрования при помощи `aesgcm.Open`, используя `nonce` и `ciphertext`;
- 3.5. Клиент сохраняет ключ в кэш в формате `map[key_id]aeskey`.


### Процесс шифрования данных на стороне клиента
Для каждого приватного поля:
1. Создается вектор инициализации `nonce` размером 12 байт;
2. Создаётся cipher.Block `aesblock` посредством `aes.NewCipher` при помощи активного (актуального) ключа `aeskey`;
3. Инициализируется блочный шифр `aesgcm` при помощи `cipher.NewGCM`, используя `aesblock`;
4. Зашифровываем исходные данные при помощи `aesgcm.Seal`, испльзуя `nonce`;
5. На сервер отправляются зашифрованные данные и метаданные `nonce` и `key_id` (версия ключа, 
который использовался для шифрования).

### Процесс расшифрования данных на стороне клиента
Для каждого зашифрованного поля:
1. Клиент из запроса получает метаданные `nonce` и `key_id`;
1. Клиент в кэше находит ключ шифрования `aeskey` по `key_id`;
2. Создаётся cipher.Block `aesblock` посредством `aes.NewCipher`, используя ранее найденный ключ `aeskey`;
3. Инициализируется блочный шифр `aesgcm` при помощи `cipher.NewGCM`, используя `aesblock`;
4. Клиент расшифровывает данные при помощи `aesgcm.Open` и `nonce`;
5. Клиент сохраняет расшифрованне данные в локальное хранилище.


## Список makefile команд
- `make help`


## Запуск проекта
1. В корне проекта создайте `.env` файл и заполните его в соответсвии с `.env-example`.
2. Запустите СУБД и сервер - `make server-up`. На сервере реализован автоматический запуск миграций.
3. Серверная часть готова к использованию.
